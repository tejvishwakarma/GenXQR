Printed menus have one problem: the day you change a price, add a dish or run out of something, every copy is out of date. A QR code menu fixes that, but only if you set it up so that you can change the menu without changing the code.

## Two ways to put a menu behind a QR code

**1. A PDF of your existing menu.** If you already have a designed menu, make a [PDF QR code](/qr-codes/pdf) and upload the file; scanning opens it. Quick to set up, and it looks exactly like your printed card. The downside: PDFs are hard to read on a phone (guests pinch and zoom), large files are slow on mobile data, and every change means editing the design file again.

**2. A menu page built for phones.** You type in your sections (Starters, Mains, Drinks) and the items with their prices, and the QR code opens a clean page with a tab for each section. Text is big enough to read, guests scroll instead of zooming, and changing a price takes seconds from your phone.

For most restaurants and cafes, the second option is better day to day. Keep the PDF for a special-occasion menu or a catering brochure.

## Step by step

1. **Create a Menu QR code** in your GenXQR dashboard and give it a name you will recognise, such as "Table menu – Connaught Place".
2. **Add sections and items.** Start with what you actually serve today. Mark veg and non-veg, and add allergens where they matter.
3. **Design the code.** Add your logo in the centre and a frame with a call to action such as "Scan for menu". Keep the code dark on a light background; see our [checklist for QR codes that scan](/blog/qr-codes-that-scan-print-checklist).
4. **Test it before printing.** Scan it with an iPhone and an Android phone, under the light at your tables.
5. **Print table cards or standees.** Put the code where guests look first: at the centre of the table or on the card holder, not under the cutlery.
6. **Update whenever you need to.** Edit the menu in the dashboard and the next guest who scans sees the new prices. The printed code never changes.

## Writing a menu that works on a phone

A phone screen shows four or five dishes at a time, so the way you write the menu matters more than on paper.

- **Keep sections short and familiar.** "Starters", "Mains", "Breads", "Rice", "Desserts", "Drinks". Guests tap tabs; ten tabs with two dishes each is harder to use than five with eight.
- **Put the dish name first and keep it short.** "Paneer tikka", not "Our chef's special smoky paneer tikka with mint chutney". The extra detail belongs in the description.
- **Use the description for what helps people choose:** the main ingredients, how spicy it is, the portion ("serves 2"), or whether it takes 20 minutes.
- **Write prices the same way throughout.** "250", not "250/-" in one place and "Rs 250" in another. The page adds the currency symbol for you.
- **Remove what you don't serve.** The advantage of a QR menu is that it can be accurate today. A dish marked "not available" on half the menu loses that.

## If you are a chain: FSSAI's menu rules

Since 1 January 2022, FSSAI's display rules require food businesses with a Central Licence, or with outlets at ten or more locations, to show **calorie values, allergen information and veg or non-veg logos** on their menu cards and boards. Online food delivery has to show the same information as the outlet. Smaller restaurants are not covered by this, though many show allergens anyway.

If the rules apply to you, the GenXQR menu page has fields for allergens and a veg or non-veg mark; there is no separate calorie field, so add the calorie value to each item's description (for example "420 kcal per serving"). The page draws the marks in FSSAI's shapes and colours, but they are a guide for guests on your phone menu; check with your FSSAI adviser what your printed menu and boards must carry. FSSAI's [FAQ on display of information](https://fssai.gov.in/upload/uploadfiles/files/FAQ-%20Display%20of%20Information.pdf) is the place to start.

## Use the scan data

Because the menu is a dynamic QR code, you can see when it is scanned: a daily chart of scans, a scan log with the exact date and time of every scan, and whether guests use iPhones or Android phones. If the log shows scans bunching at 1 pm and 8 pm, that is when the menu needs to be accurate.

The analytics show total scans and unique scans: the same phone scanning the same code again within four hours counts once as unique. The Starter plan's monthly allowance counts only unique scans, so a guest who closes the menu and scans again to order dessert doesn't use up more of it.

## More than one outlet

Give each outlet its own code, so its scans are counted separately. GenXQR's [places](/features) make this simple: add each outlet as a place (with a location ID such as "DEL-CP-01" if you use them), then use **Copy to other places** on your menu code to make one copy for each. The analytics then show scans per outlet side by side.

If every outlet serves the same menu, the copies start the same and you edit each one when a price differs. If the menus are completely different, create each outlet's menu separately.

## Specials, festivals and seasonal menus

For a limited menu, such as a Diwali thali, a monsoon specials card or a weekend brunch, make a separate code for the standee or table tent instead of changing the main menu:

- **Set a start and end date** on the code (from the Starter plan), so it only works while the offer runs.
- **Add a fallback address,** such as your main menu code's link or your website. After the end date, scanners land there instead of on an "expired" page.
- **Compare it with the main menu's scans** to see whether the standee is being noticed.

## Pair the menu with reviews and feedback

The table is also the best place to ask for a review, because guests are holding their phones. Add a small [Google review QR code](/blog/google-review-qr-code) on the bill folder, or a [feedback form](/qr-codes/form) with a star rating on the table card, offered to everyone. Keep the menu code the biggest one on the card, so guests scan the right thing first.

## Common mistakes

- **Printing a static QR code that points to a PDF link.** If you ever move or rename the file, every table card breaks. Use a dynamic code so the destination can change.
- **Codes that are too small.** On a table card, the code should be at least about 2.5 cm wide. Bigger is safer.
- **Glossy lamination under bright lights.** Reflections hide parts of the code. Matte lamination scans more reliably.
- **One code for every table, then trying to tell tables apart.** The scan data can't tell which table a scan came from if every table has the same code. That is fine for a menu; if you need table-level numbers, each table needs its own code.
- **No paper fallback.** Keep a few printed menus for guests whose phones are flat or who prefer paper.

## Frequently asked questions

**Can guests order or pay through the menu page?** No. GenXQR's menu page shows the menu; it doesn't take orders. For payments, put a [UPI QR code](/blog/upi-qr-code-for-your-shop) at the counter or on the bill.

**Do guests need an app?** No. The phone's camera opens the menu page in the browser.

**How quickly do changes show?** The next scan after you save sees the new menu. Nothing needs reprinting.

**Can I use my own photos of dishes?** The menu page is text-based: names, descriptions, prices, marks and allergens. For a photo menu, upload a PDF or use an [image gallery code](/qr-codes/image-gallery).
